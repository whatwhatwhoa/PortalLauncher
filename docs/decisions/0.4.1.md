### D35.1 · 2026-10-25 · Standby's switch, kept on and easy to find (F35)
Status: built 2026-10-25 (builds, lints); not yet run on the Portal: it was not connected.

**Ask** (owner): "home long press standby no longer works, how do we enable it? Is there a way
to make it automated and easy for the user?" Then "Yes build that": the every-user part and the
optional automatic one.
**Why it stopped**: the service list on the Portal was empty. Android's
`AccessibilityManagerService` drops a package's services from that list when the package is
force-stopped (from AOSP's source; not yet seen on the Portal), and our own restore procedure
(D28.1, `gotchas.md` *Pull app files*) force-stops the launcher. An uninstall clears it too.
**What**: the launcher keeps whether the owner wants it (`home.holdWanted`, in the setup file
too): seen on, wanted; seen going off while the launcher runs (a `ContentObserver` on
`enabled_accessibility_services`), the owner turned it off, not wanted. A force stop ends the
launcher before the list changes, so it can't be mistaken for the owner's choice: found off at a
start or resume while still wanted, the launcher switches it back on if it holds
`WRITE_SECURE_SETTINGS`, else the first Home press shows "Standby is off: Launcher Settings →
Home turns it back on" for 4 s, once per start (the press that came instead of a hold).
**The row**: A opens Android's accessibility list scrolled to Portal's row, highlighted (the
`:settings:fragment_args_key` extras Settings' search uses). After that try, if Android still
restricts the switch, the row says "Restricted: A, then ⋮ → Allow" and A opens App info: the
⋮ menu's *Allow restricted settings* appears only once the gray switch was tried. With the grant,
A flips the service on and off in place.
**Why the restriction check reads an app op**: Android 13 on grays the switch for an APK
installed from a downloaded or local file. The app reads its own
`android:access_restricted_settings` op as Android's enhanced-confirmation check does: allowed,
not restricted; errored or ignored, restricted; default, the install source decides.
**Why the grant is optional**: `WRITE_SECURE_SETTINGS` comes only from `adb shell pm grant`; no
on-device prompt exists. The README gives the line; without it nothing changes.
**Rejected**: the service's own page (`ACTION_ACCESSIBILITY_DETAILS_SETTINGS` is hidden from
apps and its activity needs a system permission); a dialog on Home with A to fix it (A on Home
opens the focused app); LineageOS's hold action (system actions only, LineageOS only: D19.1).
