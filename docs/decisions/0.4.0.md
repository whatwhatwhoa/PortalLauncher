### D30.1 · 2026-10-25 · How to wake, said on the standby screen (F30)
Status: built 2026-10-25, seen by the agent on the Portal, not yet tried by the owner.

**Ask** (owner): "Text on standby screen to unlock: only appearing after registering a press.
Press same button 4 times to unlock. Disabling helper text also disables this."
**What**: "Press the same button 4 times to wake", caption type in the date's dim white, 12 dp
under the rings. It fades in (0.2 s) when a press counts and out when the count lapses (2 s
after the first press) or standby ends; another button restarts the count at one, so the line
stays while someone tries buttons. "Helper text" read as *Button hints* (Home): off, no line.
**Why faded in place**: the line keeps its room while hidden, so the block doesn't jump the
moment a press lands. "Wake", not "unlock": nothing is locked (D19.1).
**Seen once**: on the first try after an install, standby ended about 3 s after a single press;
it didn't happen again in three tries. Left for F28's stress test.

### D31.1 · 2026-10-25 · A Fitted big name (F31)
Status: built 2026-10-25, seen by the agent on the Portal (NTE, Stardew Valley), not yet tried
by the owner; the Portal was left on Fitted.

**Ask** (owner): "A setting that makes the big font normal and fits most game titles and less
of a metro UI. Doesn't get cutoff, is a bit more opaque and less weight."
**What**: Look → *Big name*: Metro (as before, the default) or Fitted. Fitted is the name as
written (not capitals), semibold, at 60% instead of 40%, 48 dp from the top so it sits under
the status, wholly on screen, between the content margins. It starts at 36% of the display size
(about 87 sp, so its line ends above the category name) and shrinks with the name's width to
20% (48 sp): about 20 characters at full size, 36 at the smallest. Longer still, it scrolls as
the Metro name does, or ends in an ellipsis while muted or with animations off.
**Why one measure**: text width grows in proportion to its size, so the name is measured once at
the largest size and scaled by the room over that width.
**Open**: whether 60%, semibold and the sizes are right is the owner's call.

### D33.1 · 2026-10-25 · Reorganizing the dock from the options (F33)
Status: built 2026-10-25, installed on the Portal, not yet tried by the owner.

**Ask** (owner): "Add reorganize dock icon options. Also update the options to when dock is
full, the 'add to dock' is greyed out with (full)."
**What**: a docked app's options from the carousel or All apps add *Move in dock* above *Remove
from dock*: it closes the sheet (and All apps), goes Home with focus on that app's dock button,
picked up as *Move* picks it up; left and right shift it, A or B puts it down. From the dock
itself the existing *Move* does this, so it isn't repeated there. With six apps in the dock, an
undocked app's options show *Add to dock (full)* in the muted color; focus can land on it, A
bumps (the edge sound) and nothing changes. Before, the row was missing, with no reason given.
**Why grayed, not gone**: the owner's ask; a missing row read as a bug. An option can now be
disabled (`Option.enabled`), so later cards can gray a row the same way.
**Open**: "reorganize" read as moving within the dock from any sheet; if the owner meant more
(a dock page listing all six to reorder), that is a new card.

### D34.1 · 2026-10-25 · Bumpers change the category; play controls on Home (F34)
Status: built 2026-10-25, installed on the Portal, not yet tried by the owner.

**Ask** (owner): "Allow a setting that enables LB and RB to change songs in home screen. R3 to
stop playing. Home screen play controls is the setting. Default L1/R1 behavior (bumpers) is to
change the home categories." Then (owner, same day): "R3 pause/play ofc not just stop".
**What**: on Home, L1/R1 now turn to the category before or after (the order of the categories
layer), its row from the start, from the row or the dock; at the first or last category they
bump. Before, they jumped five tiles along the row; that is gone. Launcher Settings → Home →
*Home screen play controls* (off by default): on, L1/R1 skip to the previous or next track and
R3 (right stick press) plays or pauses, the same media keys the quick panel sends, each with
the select chime, since nothing on screen moves. R3 does nothing elsewhere.
**Why the ends stop**: a bump at the last category says where you are; wrapping would hide it.

### D29.1 · 2026-10-25 · The README brought up to date (F29)
Status: done 2026-10-25, not yet read by the owner. Retaken on the Portal: `settings.jpg`,
`art.jpg` (the scene grid with its tabs), `options.jpg` (gray, *Add to dock (full)*) and the
quick panel, now `quick-settings.jpg` (a photo behind it: 205 KB, the PNG was 778 KB).

**Ask** (owner): "Updated GitHub home page: updated instructions on most current features. Do
this last."
**What**: the button table gains B's edit mode, Y closing All apps, R3 and Hold Home; the
how-to bullets gain Move, Move in dock and the full dock, editing categories and Hide; *Game
art* says how the picker works (preview, grids, L1/R1 tabs, *Gallery…*); *Quick settings* the
10 s seek and the music line on Home; a new *Standby* section; *Make it yours* lists each
settings page, *Sound* included; "version 0.1" became "isn't at 1.0 yet"; sounds in *Credits*.
**Why the accessibility paragraph** (F19's question on softer wording): Android's own warning
says the service can see the screen and control the device; the README says plainly that this
one only receives the Home button (`canRetrieveWindowContent` false) and points at the code,
rather than playing the warning down.
**Why smallest width 600 is a step, not a must** (owner asked whether users need it): the root
scales the layout to whatever density Android runs at (`architecture.md` *Scaling*), so 314
(LineageOS) or 360 still fit, at 0.92 and 0.8; only at 600 dp (density 288) does every icon and
image land 1:1. So install step 4, "recommended", with the way back (dropped, below).
**Tried at stock densities** (owner asked, 2026-10-25): from a fresh start, 360 (the Portal's
built-in, `wm density reset`, 480 dp) is pixel for pixel the same as 288 (factor 0.8 gives 1.8
again), and 314 fits too (0.92). But **changing the density while the launcher runs** leaves it
drawn ~1.25× too big (the row over the name, the dock over the hints) until it restarts:
`configChanges` includes `density`, so the activity isn't recreated, and the canvas is measured
against the old density (`gotchas.md` *BoxWithConstraints' maxWidth goes stale*).
**Fixed** (owner: "just check that setting and apply the correct scale, as long as it's
reliable", same day): the scale was already computed, not a table, so any value works; the root
now sizes the window from pixels over the current density, and keeps the launcher running (no
recreate, so focus and layers stay). The floor went 0.75 → 0.5: LineageOS's largest *Display
size* (408, factor 0.7) overflowed ~7% at 0.75. Seen on the Portal, live changes without a
restart: 360 → 288 → 360 → 314, 408, 471 → 288, each Home matching 288's. Install step 4 is gone;
*Good to know* says any display size works. The Portal is back at 288. The service's description in `strings.xml` still said
"any button"; it now says the same button four times, triggers not counting (next build).

### D28.1 · 2026-10-25 · The stress test (F28)
Status: done 2026-10-25 (two debug runs, then one on the R8 build before the release). Two
bugs found and fixed, seen fixed on the Portal; nothing for a new card.

**Ask** (owner): "a bug hunt the agent scripts and runs: load the systems, press every button,
try to break it; what breaks becomes a fix or a card."
**The script**: `tools/stress/stress.py` (standard library, `py -I`). Weighted random keys
(movement most, Home rarely), bursts as fast as `input` sends them, long presses, random taps
and swipes, standby opened by its intent and pressed at, live `wm density` changes (360, 314,
408, 471, back to 288), animations off for a stretch. Every 40 steps: the pid, the crash
buffer, `am_anr`/`am_crash`, the launcher finishing itself, PSS and live activities; at the end
the launcher's warnings and `gfxinfo`. `--standby` runs timed standby checks instead.
**Why it can run on the owner's install**: a key goes only to the launcher (the focused window
is checked before each); after A, a tap or a long press it watches the focus 1.5 s and anything
else (an app, the uninstall dialog, a settings page, a picker) gets Home, never A. It still
changes the launcher's data (hides apps, deletes categories, clears art), so: back up with
`adb exec-out run-as io.github.whatwhatwhoa.portallauncher tar -cf - shared_prefs files > app.tar`,
put back with `sh tools/stress/restore.sh app.tar` and compare the prefs byte for byte (Android
restarts Home the moment it is force-stopped). Brightness, Do not disturb, the animator scale,
the density and the speaker's music volume are read first and put back by the script.
**Run 1** (1118 steps, 10 min): no crash, ANR or restart, but PSS climbed 157 → 687 MB and
`dumpsys meminfo` counted **15 activities**. Two bugs:
- **Back at home finished the launcher.** With nothing open, `BackHandler` was disabled, so
  Android's own back ran; a Home activity isn't a launcher task, so it is finished and Home is
  rebuilt in a new task (20 times in the run, each after a BACK key: the touch back gesture
  does the same). Now the handler is always on and back with nothing open does nothing, as in
  Launcher3. `KEYCODE_BACK` never reaches `dispatchKeyEvent` (predictive back takes it first).
- **Every old activity stayed in memory**, with its Compose tree, decoded art and a SoundPool
  (36 codec instances each). A heap dump, read by a small HPROF path finder: `LauncherApps`
  taken from the activity, its callback's binder stub a JNI global after `unregisterCallback`,
  holding the service, its `ContextImpl` and the activity. `AppCatalog` and `DeviceControls`
  (the media sessions listener, the same pattern) now take their services from the application.
  Checked: three recreations (font scale 1.15 ↔ 1.1, put back) leave one activity after GC.
**Run 2** (1163 steps, 10 min, the fixes): no findings; PSS between 190 and 290 MB with no
climb (art and the glow decode at screen size: the graphics share is about 170 MB); no finish.
Jank under mashing: 3% of frames, 99th percentile 28 ms.
**Standby (D30.1's lead)**: not reproduced. Eight timed trials (one press of B, X, R1 or Up,
4 s, still in standby; four presses wake), after two reinstalls, and with Home, Triangle and Square as the
press. The one sighting stays unexplained; if it comes back, `adb logcat -b events` shows
whether the activity stopped (`wm_on_stop`) or the process died.
**Run 3, the R8 build** (2026-10-25, before the release; `releaseCheck` beside the owner's
install, 580 steps, 5 min): no findings, no R8 error; PSS 196 → 245 MB max, 220 at the end; one
activity alive at most; janky frames 2.9%, 99th percentile 26 ms. The check copy was uninstalled.
**Not covered**: the hold-Home service (off on the Portal during the test), package installs
while open.

### Release · 2026-10-25 · 0.4.0, the first public release
Status: done 2026-10-25 (owner: "do all the release steps and make the GitHub public, MIT").

**What**: versionCode 4, versionName 0.4.0; `assembleRelease` + `lintRelease` clean; the APK
(3.6 MB, APK Signature Scheme v2, the release key of `M8-release.md`) carries no SteamGridDB key
(checked by searching the unpacked APK). Published as GitHub release `v0.4.0` with the asset
`PortalLauncher-0.4.0.apk`: the tag without its "v" is what Updates compares with `versionName`,
and the README's *Download* link is `releases/latest`. 0.1.0–0.3.0 got no GitHub release: they
were never public, and Updates only reads the latest.
**The history was purged before going public.** The `concepts/` files (Reddit mock-ups,
downloaded wallpapers: other people's images, about 16 MB) were deleted in `48ab1ad` but still
in the history; `git filter-branch --index-filter` removed the folder from every commit, then a
force push. Nobody else had a clone (the repo was private). Checked before: no key or password
in any commit, one author. A bundle of the old history stays local
(`C:\Users\Jim\.android\PortalLauncher-pre-purge.bundle`).
**Rejected**: a fresh repo with one squashed commit (loses the history the decision entries
point at); publishing with the images in the history (rule 2: the owner's design input stays
out of the repo).
