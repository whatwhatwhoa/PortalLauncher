### D21.1 · 2026-10-25 · The player's row in the quick panel (F21)
Status: built 2026-10-25, reshaped after the owner's first look the same day; the seek bar not yet tried.

**Ask** (owner, card F21): "back and forward button tiles … for music player. Put it above the
brightness, but the default is always brightness … When quick setting is engaged, LB and RB
controls skips. make sure glyphs are added."
**Read as**: previous and next track (Android's media keys, as a headset sends; "the normal
seek options"), not seeking inside a track. "Glyphs" as both the icons (Material Symbols
*skip_previous*, *skip_next*, the family the panel uses) and the drawn L1/R1 bumpers either side
of the row, as the Art… tabs show them (hidden with *Button hints* off).
**What**: a new top row ⏮ ⏯ ⏭; the panel still opens on Brightness, Up reaches the row. L1 and
R1 skip from any row without moving focus, with the Select sound, since nothing on screen
changes. *Play / pause* moved here from the toggles row, so the three player buttons sit
together; the toggles row is Auto brightness and Do not disturb. The owner should say if they
want it back among the toggles.
**Owner's follow-up** (same day, after trying it): "Bump it up top edge and center it. If the API
allows show the seek. Make sure the first opening locks into brightness first. Add a faint line
to separate it too." So the player row sits centered 16 dp under the panel's top edge (between
the status corners, so the panel's usual `sheetTop` isn't needed there), a seek bar under it, a
1 px line in the rule color, then Brightness. Focus starts on Brightness from the first opening
(the row index starts there too, not only on each open).
**The seek bar**: Android gives an app the playing track's position, length and seeking
(`MediaSessionManager.getActiveSessions`) only while it holds notification access, so the
launcher has an empty `NotificationListenerService` (`MediaListener`) that reads nothing, off
until the owner turns it on; A on the row opens Android's page for that one switch. The bar
shows the time in, the track and the length, re-read every 0.5 s while the panel is open;
Left/Right seek 10 s (held repeats, the slider tick), a tap jumps there; the line below names
the track. Nothing playing, or a player that can't seek: a bare track. Prev/play/next stay
media keys, so they work without the grant.
**Then** (same day): "make all the music controls single lined", and without the grant "the
allow seek option tiny … all the way to the right … [Enable Seek]". So one line: L1 ⏮ ⏯ ⏭ R1,
then the seek bar taking the rest; on the controller the bar is the row's fourth stop, right of
⏭, where Left/Right seek and Up/Down leave the row (as Android TV players do; back in, focus
lands on ⏮). Without notification access the bar is only a small *Enable seek* pill at the
line's right end (sentence case, as the rest of the UI); A or a tap opens the grant page.
Last: "pass the artist information … follow normal UI convention … stack above the seek bar
(non selectable)". So title, then " · artist" muted (the artist, else the album artist), one
caption-size line that ellipsizes, over the times and track, in the same 56 dp as the buttons;
"Nothing playing" muted when no session. The note line says "Seek" there now.

### D23.1 · 2026-10-25 · Art chosen from the preview (F23)
Status: built 2026-10-25, installed on the Portal, not yet tried by the owner.

**Ask** (owner): "instead of going through the menu, you scroll UP, and it'll select the
preview, so you can change it based off there. Closer to WYSIWYG. The larger hero/scene can be
set within that submenu instead."
**Read as**: "tile setting" is the Art… page (the tile's art), and "the preview" is the cover
and strip it already showed at its top. The owner should say if they meant Up on Home itself.
**What**: Up from the first row selects the preview; left and right go between the cover and
the wide strip; A opens that slot's grid. The five menu rows (*Choose the cover/hero/scene…*,
*Cover/Scene from the gallery…*) are gone: the gallery is a *Gallery…* tile at the head of the
cover and scene grids, so the list below the preview is only matches, *Search* and *Use the
app's icon*. The strip opens on what it shows (the scene when there is one, as Home does) and
L1/R1 turn its grid between scenes and heroes: that is "the larger hero/scene set within that
submenu", and it leaves which one wins to F24.
**WYSIWYG**: the focused thumbnail stands in the preview before A, from the thumbnail already
fetched for the grid (no extra download), so a choice is seen at the preview's size and shape
first; the preview's ring holds still while browsing (as a lifted tile does) so the pulsing one
is the grid's. B from a grid goes back to the preview, not the rows.
**Not done**: a full-screen preview of Home with the candidate (the picker sits over Home, but
Home only changes on A, after the download); worth it only if the owner asks.
**Owner's follow-up** (same day, before trying it): "multiple options to mess with the art …
consolidate in the same place", the L1/R1 caption as "actual bumper icons", and the panel may
grow ("takes up only about 1/3"). So the panel widens to 600 dp on Art… (sliding, `Dimens.artSheet`),
the preview is 120 dp tall, the grids go four, three and two across, and the caption's "R1
heroes" became tabs between drawn bumpers (`BumperGlyph`, beside `ButtonGlyph`). The per-app
hero or scene is D24.1; Launcher Settings keeps only the global art rows (key, Fetch art, Clear
all art, Covers on tiles).
**Unmatched apps**: their grids are the gallery tile alone, with "No game matched: choose one
below, or from the gallery", so the preview works for any app; without a SteamGridDB key it is
how gallery images are set at all.

### D24.1 · 2026-10-25 · Hero or scene, per app (F24)
Status: built 2026-10-25, installed on the Portal, not yet tried by the owner.

**Ask** (owner, card F24): "Choosing Hero or Scene is either or … you can only set to either one
… make sure we only render one of the options, including effects on top of that option." Then:
"Remove the option for scene/banner in launcher setting, and put it all in the tile settings."
**Name**: *Hero* stays. The owner's rule was Banner unless SteamGridDB says hero, and SteamGridDB
calls its 1920×620 images heroes.
**What**: each app shows its hero or its scene behind Home (`Art.wide`): the owner's choice,
else the scene when there is one (as Scenes on did, the old default). The choice is made in the
strip's grid by taking an image from its *Hero* or *Scene* tab, or by A on the one already
dotted; it is kept per app (`<package>.wide` in `picks`) and dropped with the icon or another
game. The global *Scenes* switch is gone (its stored `look.scenes` is ignored; an owner who had
it off sees scenes again until they pick Hero per app).
**The conflict**: Home already drew only one of the two, but *Hero glow* drew the hero blurred
behind a scene's vignette, so a scene app showed both. Now the glow follows the choice (none
under a scene), and the reflection only ever comes with the hero.
**Why per app, not a default**: the owner asked for all art in one place; a global default would
be a second place. Easy to add back if the owner wants new apps to start on the hero.
**Owner's answer** (B6.1, same day): the 600 dp panel "looks good"; "make the default behavior
pull the first hero art from steamgriddb if API key is loaded". So without a choice an app shows
its hero (SteamGridDB's first 1920-wide one, as fetched since M4), and the scene only when chosen
or when there is no hero (a game SteamGridDB has none for; a gallery scene on an app without a
game, which picking already sets). Still no global setting. Apps that showed their scene only
by default turn to their hero; on the Portal only NTE had a scene, already set to Hero.
