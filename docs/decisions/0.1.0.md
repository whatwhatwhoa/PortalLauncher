### D9.1 · 2026-10-25 · Hero reflection (F9, T9.1)
Status: accepted 2026-10-25, the mirror line replaced by a gap in D20.1 (`0.2.0.md`) (owner tried it: "looks good but more darken"; darkened from ~62%
to ~40%, that build not yet seen).

**Ask** (owner): "keep the hero gradient but also add a blurred/darken mirror, so like a soft
windy moonlight reflection", for the space under the band when an app has a hero but no scene.
**Why**: the mirror line sits inside the band's own fade (80% down), so band and reflection
meet where both are faint; a line at the band's edge put a bright strip against its fully faded
bottom. Blurred more down than across so it streaks like light on water; swayed before it is
blurred so the ripples stay soft. Light themes are only desaturated: a dark patch on a light
page reads as a smudge. A switch like the other effects, so it can be judged against its absence.
**Cost**: one layer redraws each frame while a band shows; the focus pulse already redraws Home,
so no new wakeups.
**Rejected**: mirroring the whole screen (the carousel would mirror too and fight the tile
depth); a gradient of the hero's colors (not a reflection, and Hero glow already does color).

### D10.1 · 2026-10-25 · Starting categories (F10, T10.1)
Status: accepted 2026-10-25 (owner's answers: unknown apps → All apps only; table apps
installed later → All apps only, "correct"; Chrome to Utilities).

**Ask** (owner): "ship it with the most popular apps in their default categories, so if users
have those apps, it'll place there. After that, newly installed apps go into all apps and don't
populate home."
**Why the table wins over the manifest**: manifests are often empty or odd (Chrome declares
itself social); the table is the curated answer. Only package names known for certain are in it.
**Why unknown apps go to All apps only**: Home holds only what can be placed with confidence
(owner); the first build put them in Utilities, which filled it with system odds and ends.
**Why first install time as the cutoff**: it survives updates, so an updated app never moves,
and no list of known packages has to be stored. A reinstall counts as new. The cutoff is set on
the first run of the version that has it, so an existing install keeps its apps' places.
**Rejected**: placing table apps installed later in their category (the ask is that a new install
never changes Home); a list of seen packages (grows forever, and gets lost with the data).

### B5.1 · 2026-10-25 · The dock's Launcher Settings button
Status: accepted 2026-10-25 (owner: "it looks good").

**Ask** (owner): "use our launcher icon + gear or something. Too many gears." The dock had
Android's Settings (a gear) beside ours (a gear), and the quick panel has one too.
**Why**: the launcher's own icon says "this launcher's"; the small gear badge says "settings".
**Rejected**: a gear in place of the icon's middle tile (unreadable at 56 dp); a sliders glyph
(still says "settings" without saying whose).
